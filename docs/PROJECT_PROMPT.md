# Промпт проекта DynoTranslate (для агента, каждым циклом)

Ты работаешь над DynoTranslate — динамическим экранным переводчиком EN→RU для Windows
(Tauri + Rust + ONNX, оверлей поверх чужого окна). Прежде чем трогать код, перечитай этот
файл целиком. Цель важнее текущей задачи: сначала цель, потом код.

## Цель (нордстар)

Инструмент, с которым играют в динамичные игры, читают комиксы и статьи: перевод появляется
быстро, связан по смыслу с оригиналом и с соседними репликами, и вставлен настолько органично,
что невозможно понять, что страница была переведена. Эталон качества — современные ИИ-переводчики
фото: мультимодальная модель видит всю страницу целиком и возвращает связный перевод, а пайплайн
стирает оригинальный текст (inpainting) и typeset'ит перевод в те же пузыри тем же стилем.
«Перевод по фото из Яндекса», накрывающий кадр белыми плашками, — это анти-эталон.

## Что показало исследование существующих инструментов

1. **LunaTranslator / VNTranslator** (динамические игровые переводчики): захват текста тремя
   способами — хуки памяти (Textractor-подход), OCR, буфер обмена; десятки движков перевода
   (Google, DeepL, LLM) переключаются настройками; LLM-режимы держат контекст предыдущих реплик
   для связности; оверлей рисует перевод поверх оригинала или в отдельном окне.
2. **RSTGameTranslation**: экран → OCR → дедупликация по похожести → ИИ-перевод (Gemini/ChatGPT/
   Google/Ollama) с контекстом предыдущих переводов и описанием игры; все пороги (уверенность
   OCR, settle time, похожесть, размер фрагмента) — открытые настройки, потому что одни и те же
   числа не подходят разным играм.
3. **manga-image-translator / Koharu / BallonTranslator** (бесшовные комикс-пайплайны):
   детекция текста (Comic Text Detector) → OCR (manga-ocr 48px) → перевод (DeepL/OpenAI/NLLB) →
   **inpainting (LaMa large — стирает оригинальный текст и достраивает фон)** → typesetting
   (шрифт, вписывание в пузырь). Koharu — доказательство, что весь такой пайплайн реализуем на
   Rust. Бесшовность = именно inpaint + typeset, а не плашка.
4. **Textractor**: для поддерживаемых движков текст лучше снимать из памяти до растеризации —
   тогда OCR вообще не нужен; это опциональное будущее улучшение, не ядро.

Вывод: качество складывается из (а) связного перевода с контекстом, (б) стирания оригинала и
органичной вставки, (в) открытых настроек, потому что разные игры требуют разных порогов.

## Наша архитектура (что уже есть в коде)

- `live.rs`: цикл — захват окна → даунскейл → PP-OCR det+rec (`readtext.rs`) → гейты
  (кириллица/шум/уверенность — каждый skip в журнале со своей цифрой) → перевод батчем за тик →
  компоновка оверлея. Журнал: `%LOCALAPPDATA%\DynoTranslate\live.log`, путь виден в UI.
- `backends.rs`: `google` (без ключа), `deepl` (ключ), `openai` (ключ; получает ВСЕ строки тика
  одним запросом плюс контекст предыдущих пар EN→RU — это даёт связность), локальная MarianMT —
  страховка при любой ошибке сети, оверлей не замолкает никогда.
- `settings.rs`: шестерёнки владельца, читаются циклом каждый тик и применяются к следующему же
  кадру без перезапуска; хранятся в `settings.json` рядом с журналом. Шестерёнки: стиль оверлея
  (Seamless/Плита/Субтитры), движок перевода, пороги уверенности, размер шрифта, строк за тик,
  прозрачность, длина контекста, ключи.
- `crates/render` + `crates/overlay`: `OverlayStyle::Seamless` уже стирает оригинал (erase/
  inpaint) и рисует перевод на его месте, с вписыванием и fallback на плиту при низкой
  уверенности; `Subtitles` — лента внизу. Это и есть наш бесшовный режим, включён по умолчанию.

## Принципы (нарушение = регрессия)

1. Скриншоты и live.log владельца — ground truth. Никаких предположений о поведении.
2. Каждое число-порог живёт в настройках и печатается в журнал вместе с решением. Порогов,
   которые агент крутит в коде и пересобирает билд, больше нет — владелец крутит шестерёнки сам.
3. Связность перевода первична: батчи строк экрана + контекст для LLM; одиночные строки —
   только как fallback.
4. Бесшовность первична: Seamless по умолчанию; плита — только осознанный выбор или fallback.
5. Покрытие не ронять: гейты только против доказанного мусора; любое новое ограничение сначала
   видно в журнале как skip reason с цифрой.
6. Локальная модель — страховка и офлайн-режим, а не эталон качества; эталон — сетевые LLM/API.
7. Динамичность: тик не должен блокировать; строк за тик и cadence стриминга — настройки.
8. Репозиторий: Conventional Commits, ветка одна, CI — только Rust-верификация, workflows не
   трогать, STATUS.md фиксирует проверенное/непроверенное, отвечать владельцу по-русски.

## Дорожная карта

- **M7 (готово в коде, ждёт билда)**: настройки + 4 бэкенда + Seamless по умолчанию.
- **M8**: дедупликация похожего текста между кадрами (как Text Similarity в RST), settle time,
  разбиение сверхшироких боксов детектора (два пузыря в одном rect) по зазорам.
- **M9**: настоящий inpainting сложного фона (LaMa в ONNX) вместо текущего простого erase —
  для текста поверх арта, а не только белых пузырей.
- **M10**: мультимодальный режим «весь кадр в LLM» (vision) как опциональный бэкенд: модель
  получает картинку и возвращает переводы с привязкой к боксам — тот самый уровень «никто не
  поймёт, что переведено».
- **M11 (опционально)**: хуки текста для поддерживаемых движков по образцу Textractor.

Каждым циклом: читай журнал и скриншоты владельца → меняй код → fmt/tsc → коммит → блокирующе
жди CI и Release → обнови STATUS.md → ответ по-русски с тем, что проверено и что нет.
